# AI 辅助测试用例生成与导出工具

一个基于 Streamlit 的本地测试用例生成工具。用户填写需求模板后，可以选择规则生成或 AI 生成测试用例，并导出 Excel。

当前版本：`v0.2.1`

## 功能简介

- Streamlit 单页面入口
- 需求模板输入：项目、模块、角色、前置条件、业务流程、验收标准、异常规则
- 支持上传 `.txt` / `.md` / `.docx` 需求文本并自动填充模板字段
- 支持规则生成和 AI 生成
- 支持 DeepSeek 和 OpenAI
- 当前重点支持功能测试
- 接口测试已提供文档解析 MVP：接口文档输入、字段解析、手动修正、样例用例编辑和接口 Excel 导出
- Web UI/App 测试作为后续方向或预留模板
- 支持覆盖类型配置：正常流程、异常场景、边界/非法输入、权限控制、重复操作、数据一致性、弱网/超时、状态流转、兼容性
- 自动拆分业务流程中的多个功能点
- 页面展示实际生成方式、服务商、模型、功能点数量和用例数量
- 测试用例字段包含：用例编号、模块、功能点、标题、前置条件、测试数据、步骤、预期结果、优先级、类型、备注
- 生成后可在页面表格中编辑用例，再导出编辑后的 Excel
- 按模块/功能点分组查看生成结果
- 支持单个功能点重新生成，避免整批重跑
- 自动检查用例质量：重复编号、缺字段、步骤过短、预期结果过泛、按功能点检查覆盖类型缺口
- Excel 导出包含边框、筛选、冻结表头、优先级颜色和适配行高
- 生成结果自动保存为本地 JSON，可导入历史 JSON 继续编辑
- 可从本地历史 JSON 列表中选择历史记录继续编辑
- Prompt 文件化，当前功能测试 Prompt 位于 `prompts/functional.md`
- Excel 导出包含 `测试用例` 和 `质量报告` 两个 sheet
- 生成前预览识别到的功能点和预计用例数，确认后才调用 AI 或规则生成
- 功能点识别优先使用“业务流程/需求描述”，避免把项目名称、验收标准、异常规则逐条拆成独立功能点
- 预览区展示当前覆盖策略，并按“功能点数 × 覆盖类型数”估算用例数量
- 生成前功能点以表格展示，可取消误识别功能点，被取消的功能点不参与生成
- AI prompt 会同步传入覆盖类型，规则生成会按覆盖类型选择模板
- 生成结果展示质量评分和覆盖矩阵
- 覆盖矩阵展示每个覆盖项是否命中、命中用例编号和补充建议
- 质量检查区域默认折叠，减少页面刷屏
- 编辑检查提示按分类汇总展示
- 规则生成会把长需求片段转换为较短的功能点名称和用例标题
- 用例备注保持简洁，只记录生成方式、覆盖类型和人工复核提示
- 页面采用步骤式流程：需求输入、生成计划预览、生成结果、编辑与质量检查、保存与导出
- 单功能点重新生成支持侧重点：综合补全、异常场景、边界场景、权限场景、数据一致性
- 历史 JSON 加载入口放入侧边栏折叠区
- 接口测试模式独立于功能测试流程，当前不接 AI、不做规则生成、不生成 pytest 脚本
- 提供 `examples/` 示例需求文件，可直接上传体验
- 支持 Excel 导出
- AI 调用失败时自动回退到规则生成，并显示回退原因

## 运行步骤

1. 用 PyCharm 打开本目录。

2. 创建并选择虚拟环境。

3. 安装依赖：

```bash
pip install -r requirements.txt
```

4. 启动页面：

```bash
streamlit run app.py
```

Windows 下也可以运行：

```bash
run_app.bat
```

5. 打开终端显示的地址，通常是：

```text
http://localhost:8501
```

`app.py` 底部保留了：

```python
if __name__ == "__main__":
    main()
```

因此在 PyCharm 中也可以右键运行文件；但 Streamlit 项目更推荐使用 `streamlit run app.py`。

## 环境变量

在项目根目录创建 `.env`，填写自己的 key：

```text
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4.1-mini

DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

说明：

- `.env` 存放真实 API Key，不要提交到 Git。
- 未配置 API Key 时，选择 AI 生成会自动回退到规则生成。
- 页面显示 `实际生成方式 = AI 生成（DeepSeek）` 或 `AI 生成（OpenAI）` 时，才表示本次真的调用了 AI。

建议使用方式：

1. 上传示例需求文件。
2. 检查自动填充的项目、模块、业务流程、验收标准和异常规则。
3. 在侧边栏选择覆盖类型。
4. 点击“预览生成计划”。
5. 在功能点表格中取消明显误识别的功能点。
6. 确认功能点和预计用例数合理后再生成。

## 使用建议

需求文件支持 `.txt`、`.md`、`.docx`，不需要严格固定格式。工具会尝试识别这些常见字段：

- 项目/系统名称
- 业务模块
- 使用角色
- 前置条件
- 业务流程/需求描述
- 验收标准
- 补充规则/异常场景

识别不到的正文会放入“业务流程/需求描述”，避免丢失内容。导入后仍建议人工检查并调整字段。

`.docx` 当前只抽取正文段落文本，不处理图片、表格、批注或 OCR。

生成前应先检查预览区：

- 功能点数量是否异常偏多
- 是否符合业务流程中的主要操作节点
- 覆盖类型是否符合当前需求风险
- 预计用例数是否符合预期

预览和生成数量以“业务流程/需求描述”为主要拆分来源；项目名称、角色、前置条件、验收标准和异常规则会作为完整需求上下文参与 AI 生成，但不会再默认逐条当成功能点。

覆盖类型会影响生成数量和质量检查。默认覆盖：

- 正常流程
- 异常场景
- 边界/非法输入
- 权限控制
- 重复操作
- 数据一致性

如果需求包含弱网、超时、状态变化或多端适配风险，可以在侧边栏额外勾选：

- 弱网/超时
- 状态流转
- 兼容性

生成测试用例后，优先检查这些内容：

- 功能点是否拆分合理
- 用例标题是否简洁、能表达测试意图
- 用例编号是否重复
- 操作步骤是否可执行
- 预期结果是否明确
- 每个功能点是否缺少所选覆盖类型

质量评分说明：

- 基础分为 60 分。
- 覆盖正常流程、异常场景、边界/非法输入、权限控制、重复操作、状态流转、数据一致性会获得加分。
- 操作步骤过短、预期结果过泛、测试数据为空会扣分。
- 分数限制在 0 到 100 分之间，仅作为辅助判断，不替代人工评审。

覆盖矩阵说明：

- 每一行代表一个覆盖项。
- “是否覆盖”表示是否识别到对应类型的用例。
- “命中用例”展示命中的用例编号。
- “建议说明”用于提示缺失覆盖项该补什么。

页面表格可以直接编辑。点击导出时，系统会使用编辑后的表格内容生成 Excel。

如果只对某个功能点不满意，可以在“单功能点重新生成”区域选择对应模块/功能点并重新生成。系统会替换该功能点下的用例，保留其他功能点。

重新生成时会带上原始完整需求上下文，并支持选择侧重点：

- 综合补全
- 异常场景
- 边界场景
- 权限场景
- 数据一致性

重新生成后会尽量保留原功能点的编号段，例如 `TC-02-01`、`TC-02-02`。

生成后会自动保存：

```text
outputs/latest_cases.json
outputs/cases_YYYYMMDD_HHMMSS.json
```

`outputs/` 是本地运行产物，不提交 Git。

历史 JSON 会保存本次覆盖类型。重新导入后，质量检查和导出质量报告会继续使用该覆盖策略。

## 接口测试 MVP

侧边栏“用例生成类型”选择“接口测试”后，会进入独立的接口测试页面。

当前支持：

- 粘贴接口文档并按标题解析字段
- 解析后手动修正项目、模块、接口名称、请求方法、接口路径、鉴权方式、请求头、请求参数、请求体、响应示例、业务规则、数据库校验
- 生成 3 条接口测试样例
- 页面表格编辑接口用例
- 导出 `接口测试用例` Excel sheet

当前可识别的接口文档标题包括：

- 项目/系统名称、项目名称、系统名称
- 业务模块、模块
- 接口名称
- 请求方法
- 接口路径、请求路径、URL
- 鉴权方式、鉴权、认证方式
- 请求头
- 请求参数、字段说明
- 请求体
- 成功响应、失败响应、响应示例
- 业务规则
- 数据库校验

解析器不要求文档完全固定格式，但建议每类内容尽量使用独立标题。缺少字段时可以在页面解析结果区手动补充。

当前暂不支持：

- AI 生成接口用例
- 根据 Swagger/OpenAPI 自动解析
- 发送真实接口请求
- 生成 pytest 或自动化测试脚本
- RAG、数据库、FastAPI

如果导出的 Excel 没有看到 `质量报告` sheet，请先停止旧的 Streamlit 服务并重新启动：

```bash
streamlit run app.py
```

旧服务进程可能仍在使用旧版导出代码。
